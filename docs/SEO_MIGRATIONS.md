# SEO Migrations Manifest

All six SEO migrations must be applied manually via the Supabase SQL Editor in the order listed.
None are applied to production automatically. The backend has no migration runner; these are
hand-applied DDL files. All DDL is `IF NOT EXISTS` / `ENABLE RLS` — idempotent and safe to re-run.

## Ordering Notes

The ordering enforced by filename timestamp is correct:

1. `20260728_seo.sql` — must be first: establishes `seo_sites` which all later migrations reference via `data->>'site_id'`.
2. `20260729_seo_search_intelligence.sql` — must follow migration 1: references site_id and establishes `seo_opportunities` referenced by outreach.
3. `20260730_seo_backlinks.sql` — requires migration 1 (site_id); can run in parallel with migration 2 but timestamp ordering is safe.
4. `20260731_seo_local.sql` — requires migration 1 (site_id); can run independently of 2 and 3 but timestamp enforces correct order.
5. `20260801_seo_outreach.sql` — references `opportunity_id` from migration 2 (`seo_opportunities`); must run after both 1 and 2.
6. `20260802_seo_reports.sql` — references `site_id` from migration 1 only; can run after migration 1, but timestamp ordering places it last.

**Minimum dependency chain:** 1 → 2 → 5 (outreach references opportunities from 2).
All six can be applied in timestamp order without issue.
